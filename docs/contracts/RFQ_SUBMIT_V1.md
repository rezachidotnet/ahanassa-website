# rfq_submit.v1 — browser → RFQ Worker

Endpoint: `POST https://api.ahanassa.com/api/rfqs` (architecture V1.1 §6.1, A4). Until W2 the static
`/contact` page still posts to the current same-origin `/api/rfqs`; the payload is the same.
Code twin: `lib/contracts/rfq-submit-v1.ts` — field limits are imported from the running validator
(`lib/rfq/validation.ts`, `item-row-validation.ts`, `uom.ts`), so they cannot drift.

## Request

`Content-Type: application/json`; body ≤ **20,000 bytes**. **Strict:** unknown keys are rejected
(the current endpoint still ignores them; the RFQ Worker enforces strictness in W2).

| Field | Type / rule |
|---|---|
| `idempotencyKey` | 16–128 chars `[A-Za-z0-9_-]`. Generated by the browser once per "new request" (`crypto.randomUUID()`), resent unchanged on retry. The server stores only `SHA-256(key)` plus the payload fingerprint. |
| `locale` | `fa` \| `en` \| `ar` |
| `fullName` | 2–100 |
| `companyName` | optional, ≤ 160 |
| `email` | ≤ 254, `x@y.z` |
| `phoneCountry` | ISO-3166 alpha-2 |
| `phoneLocal` | 1–20; composed to E.164 on the server |
| `deliveryLocation`, `message` | optional, ≤ 200 / ≤ 3000 |
| `items` | 1–20 lines, or 0 lines when `attachments` is non-empty (file-only RFQ, owner decision 2026-10-13; otherwise 422 `items: [too_small]`): `catalogVariantXid?` (≤ 200, `[A-Za-z0-9_.-]`, canonical CVAR), `freeformTitle?`, `productSlug?`, `categoryLabel?`, `gradeOrStandard?`, `quantityText` (1–100), `unit` (`kg`, `ton`, `branch`, `sheet`, `meter`, `coil`, `bundle`, `piece`; launch policy per group), `description?` (≤ 1000), `lengthMm?` (integer, (0, 1e6]) |
| `website` | honeypot — must be empty |
| `formRenderedAt` | optional epoch ms (passive timing signal) |
| `turnstileToken` | Cloudflare Turnstile response token; action `rfq_submit`; the Worker also checks `hostname` (W2) |
| `attachments` | optional, 0–5 × `{name (1–255), size (integer, 1..15 MiB)}` — D-RFQ-FILE (`docs/RFQ_FILE_UPLOAD.md`). The Worker checks the extension and size, answering 422 `attachments[i].name: [macro_file \| executable_or_archive \| extension_not_allowed \| …]`, or `attachments: [uploads_disabled]` when upload is off. Each declared file is part of the payload fingerprint. The bytes follow, after the RFQ is accepted, with `PUT /api/rfqs/files/<reference>/<slot>` and `X-RFQ-Key: <idempotencyKey>`. |
| `catalogSnapshotVersion` | `snap-<16 hex>` from `/data/rfq-catalog.<locale>.json` (`snapshot.v1`); `null` on the legacy SSR runtime. Variants are validated against this snapshot's `rfq_variant_index` rows (fallback: active version). |

## Responses

Success body: `{"ok": true, "reference": "AA-RFQ-…", "status": "received"}`.
Error body: `{"ok": false, "code": "…", "fieldErrors"?: {"<path>": ["<reason>"]}}`. Every response
carries `Cache-Control: no-store`.

| HTTP | Body | When |
|---|---|---|
| 201 | success | new RFQ durably committed (RFQ + lines + outbox in one D1 batch) |
| 200 | success | replay: same key, same payload fingerprint — the original reference |
| 400 | `VALIDATION_ERROR` | body not JSON / unreadable |
| 403 | `VERIFICATION_FAILED` | Turnstile rejected, or `Origin` not allowed |
| 409 | `IDEMPOTENCY_CONFLICT` | same key, different payload fingerprint |
| 413 | `PAYLOAD_TOO_LARGE` | body > 20,000 bytes (`Content-Length` or actual) |
| 415 | `VALIDATION_ERROR` | `Content-Type` is not `application/json` |
| 422 | `VALIDATION_ERROR` + `fieldErrors` | schema, catalog-variant or UoM validation failed |
| 429 | `RATE_LIMITED` | rate limit exceeded; `Retry-After: 60` |
| 503 | `SERVICE_UNAVAILABLE` | D1, Turnstile Siteverify or the rate-limit binding unavailable — fail closed; the browser may retry with the same key |

## File upload (D-RFQ-FILE)

| Request | Answer |
|---|---|
| `GET /api/rfqs/files` | `{ok, enabled, maxFiles?, maxFileBytes?, extensions?}`; `Cache-Control: public, max-age=300`. `enabled` is true only with the `RFQ_FILES` binding and `RFQ_FILES_ENABLED=1`. |
| `OPTIONS /api/rfqs/files/…` | 204 for an allowed origin, with `Allow-Methods: GET, PUT` and `Allow-Headers: content-type, x-rfq-key`. Any other origin gets 403. |
| `PUT /api/rfqs/files/<reference>/<slot>` | 201 `{ok, status: "received"}`. An already received file gets 200. Wrong reference, key or slot gets 404 `NOT_FOUND` (one answer for all three). A missing length gets 411. Over 15 MiB gets 413. A size mismatch or refused content gets 422 `FILE_REJECTED` + `reason`. After the first delivery attempt the answer is 409 `UPLOAD_CLOSED`. Over the per-IP limit gets 429. A storage error gets 503 `STORAGE_UNAVAILABLE`. Upload switched off gets 404 `UPLOADS_DISABLED`. |

## CORS and CSP

- `Access-Control-Allow-Origin` is echoed **only** for an exact allowed origin; `Vary: Origin`.
  Preflight `OPTIONS /api/rfqs` → 204, `Access-Control-Allow-Methods: POST`,
  `Access-Control-Allow-Headers: content-type`, `Access-Control-Max-Age: 86400`. No credentials.
- Allowed origins: production `https://www.ahanassa.com`; staging
  `https://ahanassa-v11-static-staging.nova-b1e6f0.workers.dev` (the v11 static staging site, W2).
  Any other `Origin` → 403.
- The public page's CSP `connect-src` is exactly `'self'`, `https://challenges.cloudflare.com`, the
  target's RFQ origin (`https://api.ahanassa.com` / `https://api-staging.ahanassa.com`) and GA4's
  collection origins (`https://*.google-analytics.com`, `https://*.analytics.google.com`,
  `https://*.googletagmanager.com`; owner decision 2026-10-13, DAR-066). It is generated from
  `lib/security/headers.ts` + `lib/static/targets.ts`, and the artifact gate enforces it.
- Turnstile keys, rate limiter and `DB_OPS` are separate per environment.
